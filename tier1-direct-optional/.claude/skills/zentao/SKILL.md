# 禅道任务 / Bug

脚本：`.claude/skills/zentao/scripts/zentao.py`（下文写作 `zt`），在项目根目录执行，只依赖 Python 3.8+ 标准库。

## 一条命令开始

用户输入 `/zentao <编号或链接>`，例如：
- `/zentao 123`、`/zentao T123`：任务
- `/zentao B45`、`/zentao bug 45`：Bug
- 也可以直接贴禅道任务或 Bug 的页面链接

**只给数字时按任务处理**；用户说的是 Bug 时，传给脚本统一写成 `B45`（链接可以原样传，带空格的写法要加引号）。

### 任务

1. `python3 zt show <编号>`：读取任务描述、关联需求和验收标准。
2. `python3 zt start <编号>`：禅道里把任务标成"进行中"，开始计时。任务已经在进行中时只开始计时。
   - 报错"没有预计工时"时，问用户预计要几小时，再加 `--left <小时>` 重试。
3. 把需求和验收标准当作这次的需求，按 `AGENTS.md` 的流程（定规模 → 实现 → 检查 → 用户验证 → 提交）完成。
4. 用户验证通过、代码提交之后，进入下面的「完成」。

### Bug

1. `python3 zt show B<编号>`：读取重现步骤和关联需求。
2. `python3 zt start B<编号>`：只开始计时，不改禅道。
3. 按 `systematic-debugging` 定位根因并修复，再走用户验证和提交。
4. 进入下面的「完成」。

## 完成（工时只确认一次）

1. 运行 `python3 zt time`，得到每段工作的时间、内容摘要和建议工时。
2. 用建议工时和一句话修改摘要预览：
   - 任务：`python3 zt finish --hours <建议工时> --comment "<修改摘要>"`
   - Bug：`python3 zt resolve --hours <建议工时> --comment "<修改摘要>"`
3. 在**同一条消息**里发给用户：`time` 的分段明细、预览块，再问一句"工时按 X 小时提交吗？要改直接回复小时数"。然后**停下来等回复**。
   - 计时只包括 AI 干活的时间。用户自己看需求、review 的时间可以让用户加进来。
   - 明细里有和这个任务无关的段，或者标了 ⚠ 时长异常的段，主动指出来，建议用户扣掉。
4. 根据用户的回复执行：
   - 回复"确认 / 可以"：带上预览里的确认码执行，即在预览命令后加 `--confirm <确认码>`。
   - 回复一个新的工时：用这个工时重新预览，再用新的确认码执行。用户给出的数字本身就是确认，不用再问一次。
   - 要改备注：同样重新预览后再执行。
5. 告诉用户结果和禅道链接。

Bug 的处理细节：解决方案填"已解决"，解决版本默认"主干"（可用 `--build` 改），指派回提 Bug 的人。禅道开源版不能在 Bug 上记工时，耗时会写进解决备注。

## 计时

- 计时靠项目 `.claude/settings.json` 里的两个钩子：每轮对话开始时运行 `zt track begin`，结束时运行 `zt track end`。只记录 AI 在干活的时间，等用户回复、关掉会话的时间都不算。跨会话、跨天会自动累加。
- 中途切到和这个任务无关的事时，运行 `python3 zt pause` 暂停计时；回来时再 `start` 一次。任务已经是进行中，所以不会重复改禅道。
- `time` 一直显示"没有记录"时，说明钩子没装上。检查 `.claude/settings.json` 里有没有 `zentao.py track`，同时告诉用户可以按实际情况手填工时。
- 计时记录在 `~/.cache/zentao/` 下，不进项目仓库。任务完成或 Bug 解决后，对应的记录会被清除。

## 首次配置

禅道账号是用户个人的，写在 `~/.config/zentao/config.json` 里，并 `chmod 600`：

```json
{"url": "http://zentao.example.com/zentao", "account": "<账号>", "password": "<密码>", "allow_http": true}
```

- `url` 可以直接填禅道任意页面的地址，脚本会自动取到 `/zentao` 这一级。
- 只能用 http 访问的禅道必须写 `"allow_http": true`，否则会拒绝连接，因为密码会明文传输。有 https 就用 https，并去掉这一项。
- 用户在对话里直接给了账号密码：替用户写进这个文件并 `chmod 600`，回复里不要复述密码，也不要写进项目目录。

## 不要做

- 不经用户确认就执行带 `--confirm` 的 `finish` / `resolve`，或者自己预览完就直接提交。
- 提交用户没确认过的工时，或者私自把工时改大、改小。
- 关闭 Bug、改任务的其他字段、新建任务或 Bug。这个 skill 只做开始、完成、解决这三个动作。
- 把禅道密码写进项目文件、命令行参数或回复里。
